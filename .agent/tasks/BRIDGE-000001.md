# BRIDGE-000001 — Исследование и подготовка каркаса Altium Add-in

## 1. Контекст

Предоставлен проект InteractiveBom для Altium Designer 26 в виде бинарной поставки:
`README.md`, `publish_out/` с DLL, `.Ins`, `.rcs`, веб-ресурсами и инструкцией по установке.
Исходный код проекта не предоставлен.

В поставке подтверждены:

- точка входа `CSharpPlugin.PluginFactory.InvokePluginFactory(DXP.IClient)`;
- модуль-наследник `DXP.ServerModule`;
- регистрация команды через `CommandLauncher.RegisterCommand`;
- установка через каталог Extensions и `ExtensionsRegistry.xml`;
- сборка Add-in под `net8.0-windows` и SDK-сборки под .NET 8.

Также на стенде доступен Altium SDK 4.0.1 в составе Altium Developer:
исходники API, примеры Add-in и `.Ins`-шаблоны.

Нужно доказать, что мы можем собрать собственный каркас Add-in на согласованном стеке,
загрузить его в Altium Designer 26 и выполнить минимальное чтение платы через подтверждённые API,
не реализуя обмен с SOLIDWORKS.

## 2. Цель

Подготовить воспроизводимый каркас Altium Add-in ECAD-MCAD Bridge, который:

1. собирается на .NET SDK 10: Altium — `net10.0-windows`, Core/Core.Tests — `net10.0`;
2. загружается в Altium Designer 26;
3. регистрирует одну команду в меню;
4. читает минимальные сведения об активной `.PcbDoc` через подтверждённые `PCB.IPCB_*` API;
5. пишет диагностический JSON во временный каталог;
6. не изменяет плату и не содержит кода SOLIDWORKS.

Совместимость Altium Designer 26 + Altium SDK 4.0.1 + .NET SDK 10 с `net10.0-windows`
подтверждена оператором (C-65). InteractiveBom под `net8.0-windows` — только референс.
R-01 остаётся регрессионной проверкой загрузки, а не исследованием совместимости.

## 3. Scope

Входит:

- анализ предоставленного InteractiveBom: `.Ins`, `.rcs`, публичные метаданные сборок, поведение;
- анализ официальных примеров Altium SDK 4.0.1;
- создание solution и проектов `Core`, `Altium`, `Core.Tests`;
- минимальный bootstrap Add-in и одна команда;
- smoke-тест в Altium Designer 26;
- фиксация результатов исследования в `SDK_API_LEDGER.md`, `DECISIONS.md`, `PROJECT_CONTEXT.md`;
- обновление `README.md` командами сборки/установки;
- отчёт и PR.

Не входит:

- обмен с SOLIDWORKS;
- создание проекта `EcadMcadBridge.SolidWorks`;
- полный экспорт платы и формат Exchange Package;
- ECO, обратная аннотация, запись в `.PcbDoc`;
- 3D-модели, STEP, MCAD-геометрия;
- установщик, CI/CD, подпись, публикация;
- поддержка версий Altium, отличных от 26;
- передача пользовательских PCB, STEP и рабочих сборок через Git.

## 4. Артефакты

Ожидаемая структура (имена могут быть уточнены, но слои и границы обязательны):

```text

    EcadMcadBridge.Core.Tests.csproj
```

Требования к артефактам:

- Целевой TFM: `Core.Tests` и `Core` — `net10.0`; `Altium` — `net10.0-windows`.
- `Core` не содержит ссылок на Altium SDK, WPF/WinForms и SOLIDWORKS.
- `Altium` содержит только bootstrap, adapter, application, installation и UI-минимум.
- `.Ins` и `.rcs` описывают одну команду и корректную точку меню.
- В репозиторий не попадают DLL Altium, DevExpress, WebView2 и другие проприетарные бинарники.
- Секреты и данные заказчиков отсутствуют.

## 5. Функциональные требования к каркасу

### 5.1 Точка входа

- Класс `CSharpPlugin.PluginFactory` с `[ComVisible(true)]` и `[ClassInterface(ClassInterfaceType.None)]`.
- Метод `InvokePluginFactory(DXP.IClient client)` создаёт и возвращает модуль.
- Модуль наследует `DXP.ServerModule`, передаёт имя модуля и реализует `NewDocumentInstance`, возвращая `null`.

### 5.2 Команда

- Одна команда с ID `EcadMcadBridge:ExportSmokeSnapshot`.
- Регистрация в `InitializeCommands()`.
- Команда доступна из меню Tools в PCB-документе.
- Повторный запуск не требует перезапуска Altium.
- При отсутствии активной платы команда показывает понятное сообщение и не падает.

### 5.3 Чтение данных

Минимальный снимок:

```json
{
  "schema": "ecad-mcad-bridge/smoke-snapshot",
  "schemaVersion": "0.1.0",
  "cad": "altium",
  "cadVersion": "26",
  "documentFileName": "board.PcbDoc",
  "sourceUnits": "altium-iu",
  "units": "mm",
  "sampleCoordinate": { "xIu": 1000000, "yIu": 2000000, "xMm": 10.0, "yMm": 20.0 },
  "componentCount": 0,
  "outlinePointCount": 0,
  "exportedAtUtc": "2026-11-24T00:00:00Z",
  "warnings": []
}
```

Правила:

- имя документа — только имя файла, без полного пути;
- `componentCount` — число компонентов, полученных итератором с фильтром по типу компонента;
- `outlinePointCount` — суммарное число точек контуров board outline;
- `sampleCoordinate` содержит пару `xIu/yIu` (исходные IU) и `xMm/yMm` (результат `CoordToMMs`);
  IU не округляются и не заменяются миллиметрами;
- если outline недоступен, команда не падает: пишет warning и `outlinePointCount: 0`;
- JSON — UTF-8 без BOM, LF, детерминированный порядок полей;
- файл пишется в `%TEMP%\EcadMcadBridge\`, имя содержит UTC-timestamp;
- путь к файлу показывается пользователю;
- запись в `.PcbDoc` запрещена.

### 5.4 Логирование

- Лог в `%TEMP%\EcadMcadBridge\logs\` или `%LOCALAPPDATA%\EcadMcadBridge\logs\`.
- Записываются: версия Add-in, версия CAD, имя документа, счётчики, длительность, коды ошибок.
- Не записываются: полный путь, содержимое платы, BOM, netlist, токены.
- Ошибки не проглатываются молча.

## 6. Технические требования

1. `global.json` фиксирует .NET SDK 10.0.x.
2. TFM по проектам: `Altium` — `net10.0-windows`, `Core` и `Core.Tests` — `net10.0`;
   C#, nullable enabled, warnings as errors.
3. Altium SDK подключается через MSBuild-свойство `AltiumSdkDir`; путь не хардкодится.
4. `Core` не ссылается на CAD SDK.
5. Для каждого вызова SDK — запись в `SDK_API_LEDGER.md` с доказательством.
6. Неподтверждённый вызов допускается только как явный fallback с записью в ledger и логом.
7. Reflection/dynamic запрещены как основной путь; допустимы только для диагностики,
   если типизированный вызов не работает, и с планом замены.
8. UI — минимальный; выбор WPF/WinForms фиксируется в отчёте и, при необходимости, в ADR.
9. Длительные операции не блокируют UI; для smoke-снимка допускается синхронное выполнение,
   если оно укладывается в 2 секунды на тестовой плате.
10. Код разделён на слои: bootstrap не содержит логики чтения платы, adapter не содержит UI.

## 10. Ограничения и риски

| Риск | Влияние | Митигация |
|---|---|---|
| Регрессия загрузки `net10.0-windows` в AD26 | Блокирует каркас | Совместимость подтверждена (C-65); при повторе — остановиться, ADR D-013, не менять TFM молча |
| Несовместимость API kit 4.0.1 и runtime AD26 | Падения при вызове | Сравнить сборки, использовать runtime-совместимый вариант после ADR |
| Прямой вызов PCB API не работает | Нужен reflection | Доказать, зафиксировать fallback и план замены |
| Outline недоступен на некоторых платах | Неполный snapshot | Warning, не падать; отдельная задача |
| Неизвестная лицензия на поставку DLL | Юридический риск | Не коммитить DLL, зафиксировать вопрос |
| Тестовая плата содержит данные заказчика | Утечка | Использовать синтетическую плату |
