# BRIDGE-000025 — Runtime Validation of Body Identity Diagnostics

## 1. Цель

Получить фактические runtime-доказательства для D-024 на реальной плате AD26
26.12.2.9: для 15 участвующих designators прочитать `bodyUniqueId`,
library-level `footprintSourceUniqueId` и фактический `IPCB_Model.GetOrigin()`
через уже реализованную команду `EcadMcadBridge:ReadBodyIdentityDiagnostics`.

Затем проверить 9 Bottom/Top пар из BRIDGE-000023 по формуле D-024 §5 и
сопоставить полученный `ModelOrigin` с прежними bbox-наблюдениями. bbox не
используется как `ModelOrigin` и не подставляется в расчёт.

Задача — только валидация. Production Bottom, D-022, D-024, transform engine,
catalog и Exchange Package не изменяются.

## 6. Проверка 9 пар D-024

| Bottom | Top ref | Footprint | θ bottom |
|---|---|---|---:|
| C37 | C25 | CAP 0402_1005 | 180 |
| C34 | C25 | CAP 0402_1005 | 180 |
| C36 | C29 | CAP 0402_1005 | 270 |
| C35 | C29 | CAP 0402_1005 | 270 |
| R50 | R25 | RES 0402_1005 | 0 |
| R43 | R25 | RES 0402_1005 | 0 |
| R44 | R36 | RES 0402_1005 | 90 |
| R53 | R26 | RES 0402_1005 | 180 |
| D9 | D8 | SOD323 | 180 |

Для каждой пары вычислить из фактических values:

```text
d_top          = Rz(-θ_top) · (ModelOrigin_top.XY - ComponentPosition_top.XY)
d_bottom_local = Rz(-θ_bottom) · (ModelOrigin_bottom.XY - ComponentPosition_bottom.XY)
d_bottom_board = (d_bottom_local.X, -d_bottom_local.Y)
e              = d_bottom_board - d_top
```

Записать `e` в мм, paired IDs, `stepAssetSha256`, `bodyOrdinal` и diagnose-поля.
Сопоставить `e` и `ModelOrigin` с BRIDGE-000023 bbox-proxy:

- CAP: `e≈[0,+0.524002] mm`;
- RES: `e≈[0,+0.499999] mm`;
- SOD323: `e≈[-0.00000254,+1.25000004] mm`;
- no-flip residual ≤ `0.000006 mm`.

Эти числа — только точка сравнения, не вход расчёта и не доказательство D-024.
Фикстурное `e=+3.371315…316 mm` из R4-A (`BRIDGE_ROT_3D`) не считать
универсальным.
